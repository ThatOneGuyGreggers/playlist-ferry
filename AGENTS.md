# Project instructions

Read and follow [CODING_GUIDELINES.md](CODING_GUIDELINES.md) when writing or reviewing code, tests, comments, documentation, commit messages, and error messages in this workspace.

Apply these guidelines to the macOS app, its Python worker, packaging scripts, and project documentation. Preserve upstream spotDL conventions when working in the cloned repository unless they conflict with correctness or a specific project requirement. Keep the guidelines close to the code: document public interfaces, limits, failure behavior, and resource ownership, and verify the relevant formatter, linter, type checker, tests, and build before declaring implementation work complete.

After each meaningful change, add a dated entry to [CHANGELOG.md](CHANGELOG.md). State what changed and why, and record the LLM used for that work. Use the exact model name when it is available; otherwise write `Model not disclosed` rather than guessing. Keep entries brief and factual. Do not rewrite earlier entries when adding a new one.
